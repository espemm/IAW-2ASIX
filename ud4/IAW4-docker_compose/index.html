    Docker Compose¶

    Docker Compose és una eina que permet definir i executar aplicacions multicontenidor mitjançant un únic fitxer en format YAML (docker-compose.yml).

    És ideal per a projectes que requereixen, per exemple, un servidor web, una base de dades i un backend treballant junts. Quan se necessiten diferents contenidors funcionant a l’hora amb docker compose s’aconsegueix.

    Ordres bàsiques¶

    Crea i inicia els serveis en segon pla:

    docker compose up -d

    Mostra l’estat dels serveis del projecte:

    docker compose ps

    Para i elimina els contenidors i xarxes creades:

    docker compose down

    docker-compose.yaml¶

    En el fitxer docker-compose.yaml definim l’escenari. Les ordres docker compose s’han d’executar al directori on està aquest fitxer.

    Per tant, hem de tindre un directori amb un fitxer docker-compose.yaml per a cadascuna les aplicacions que volem desplegar.

    Per exemple, per a l’execució de l’aplicació Let’s Chat podríem tenir un fitxer docker-compose.yaml, dins d’una carpeta, amb el contingut següent:

    versió: '3.1'
services: 
  app: 
    container_name: letschat 
    image: sdelements/lets-chat 
    restart: always 
    environment: 
      LCB_DATABASE_URI: mongodb://mongo/letschat 
    ports: 
      - 80:8080 
    depends_on: 
      - db 
  db: 
    container_name: mongo 
    image: mongo:4 
    restart: always 
    volums: 
      - mongo:/data/db
volums: 
  mongo:
    Els paràmetres que podem definir estàn en la documentació oficial.

    Alguns paràmetres:

    • Aquest escenari està format per services. Cadascú crearà un contenidor.
    • restart: always Indiquem la política de reinici del contenidor si per qualsevol condició es para.
    • depend on Indica la dependència entre contenidors. No s’iniciarà un contenidor fins que un altre estiga funcionant.

    Quan creem un escenari amb docker compose es crea una nova xarxa definida per l’usuari on es connecten els contenidors; per tant, obtenim resolució per dns que resol tant el nom del contenidor (per exemple, mongo) com el nom del servei (per exemple, db).

    Més ordres¶

    • docker compose stop: Atura els contenidors que prèviament s’han llançat amb docker compose up.
    • docker compose run: Inicia els contenidors descrits al docker-compose.yaml que estiguin aturats.
    • docker compose rm: Esborra els contenidors aturats de lescenari. Amb les opcions -f també elimina els contenidors en execució.
    • docker compose pause: Pausa els contenidors que s’han llançat prèviament amb docker compose up.
    • docker compose unpause: Repreneu els contenidors que prèviament s’han pausat.
    • docker compose restart: Reinicia els contenidors. Ordre ideal per reiniciar serveis amb noves configuracions.
    • docker compose logs: Mostra els logs de tots els serveis de lescenari. Amb el paràmetre - podrem anar veient els logs en “viu”.
    • docker compose logs servei1: Mostra els logs del servei anomenat servei1 que estava descrit al docker-compose.yaml.
    • docker compose exec servei1 /bin/bash: Executa una ordre, en aquest cas /bin/bash en un contenidor anomenat servei1 que estava descrit al docker-compose.yaml
    • docker compose top: Mostra els processos que s’estan executant a cadascun dels contenidors dels serveis.
