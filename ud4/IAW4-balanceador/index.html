    Balancejador Web¶

    Balancejador de càrrega¶

    Què és el Balanceig de Càrrega?

    El Balanceig de Càrrega és un procés on tota la càrrega de treball es distribueix uniformement entre diferents sistemes, servidors i recursos computacionals. Aquesta tècnica ajuda a distribuir el trànsit entre diversos servidors de manera uniforme per millorar el rendiment i la fiabilitat. Redueix la càrrega a cada servidor, augmenta l’eficiència del servidor, accelera el rendiment i disminueix la latència.

    La majoria de les aplicacions d’Internet no poden funcionar amb èxit sense balanceig de càrrega. Al enviar sol·licituds de clients a nodes d’ordinadors inactius, se redueix la sobrecàrrega dels recursos computacionals.

    Exemple de balanceig de càrrega:

    Els balancejadors de càrrega actuen com a intermediaris entre els dispositius clients i els servidors backend, dirigint les sol·licituds dels clients a diversos servidors. Les empreses generalment trien el balanceig de càrrega per assegurar que les aplicacions estiguin actives i disponibles per als usuaris.

    Diàriament, les empreses reben centenars i milers de sol·licituds cada minut. Durant les temporades altes, el trànsit pot augmentar significativament, afectant el rendiment del servidor. Per reduir la pressió al servidor i mantenir mitjans d’alta qualitat, la majoria de les empreses utilitzen balancejadors de càrrega.

    Aquests dispositius rastregen cada sol·licitud entrant i desvien el trànsit als servidors respectius basant-se en diversos factors, evitant sobrecarregar un sol servidor.

    Avantatges d’Utilitzar Balanceig de Càrrega

    • Escalable i redueix la resolució de problemes.
    • Ofereix suport per a la Capa 4 o la Capa 7.
    • Menor ús d’ample de banda.
    • Accés ràpid i fàcil a informació de l’aplicació.
    • Protecció de múltiples servidors web.
    • Persistència de sessió.
    • Permet l’encaminament de port a port dins d’una sola instància.
    • Estalvia temps i desplega ràpidament amb balancejadors de càrrega de programari.
    • Permet que el servidor original rebutge paquets sospitosos abans que arriben.
    • Dirigeix ​​les sol·licituds dels clients mentre maximitza l’eficiència de la xarxa.
    • Permet que les sol·licituds s’envien al mateix servidor des d’un client específic.
    • Millora l’experiència de l’usuari i redueix les respostes d’error.

    Tipus de Balancejadors de Càrrega

    Hi ha tres tipus de balancejadors de càrrega:

    • DNS Round Robin: Aquest tipus de balancejador de càrrega distribueix les sol·licituds dels clients a diferents servidors. El servidor DNS respon a les sol·licituds dels clients amb una llista d’adreces IP de servidors. Els clients seleccionen una adreça IP de la llista i es connecten al servidor corresponent. Aquest mètode és simple i fàcil de configurar, però no és efectiu per a l’alta disponibilitat i l’escalabilitat.

    • Balancejador de Càrrega L3/L4: Aquest tipus de balancejador de càrrega opera a la capa de xarxa (L3) i la capa de transport (L4). El balancejador de càrrega L3/L4 distribueix les sol·licituds dels clients basant-se en l’adreça IP d’origen i destí, el port d’origen i destí i el protocol de transport. Aquest mètode és ràpid i eficient, però no és efectiu per a la capa daplicació.

    • Balancejador de Càrrega L7: Aquest tipus de balancejador de càrrega opera a la capa d'aplicació (L7). El balancejador de càrrega L7 distribueix les sol·licituds dels clients basant-se en la informació de la capa d’aplicació, com ara l’URL, la capçalera HTTP, i el tipus de contingut. Aquest mètode és efectiu per a l’alta disponibilitat, escalabilitat i seguretat.

    Implementació

    Caldrà disposar almenys de 3 servidors. Un funcionarà com a balancejador i els altres dos seran els qui aniràn rebent les sol·licituds dels clients segons les redireccione el balancejador.

    Utilitzant els dominis següents: web1.iaw2425.com web2.iaw2425.com balancer.iaw2425.com

    Podríem disposar d’aquesta configuració de balanceig de càrrega:

    Balancejador amb Apache¶

    Requisits previs:

    • 3 servidors amb Apache instal·lat
    • Configuració de noms de domini

    Configurar el Primer Servidor Backend Apache

    Crear una pàgina HTML de mostra i un fitxer de configuració de host virtual al primer servidor Apache:

    nano /var/www/html/web1.html

    Exemple de codi HTML:

    <!DOCTYPE html>
<html>
<head>
<title>Servidor Web Apache 1</title>
</head>
<body>
<h2>Pàgina del Servidor Web Apache 1!</h2>
</body>
</html>

    Crear el fitxer de configuració del host virtual:

    nano /etc/apache2/sites-enabled/web1.conf

    Afegir les següents configuracions:

    <VirtualHost *:80> 
    ServerName web1.iaw2425.com 
    ServerAdmin webmaster@localhost 
    DocumentRoot /var/www/html 
    DirectoryIndex web1.html 
    ErrorLog ${APACHE_LOG_DIR}/error.log 
    CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>

    Caldrà reiniciar el servei Apache:

    systemctl restart apache2

    Configurar el Segon Servidor Backend Apache

    Crear una pàgina HTML de mostra i un fitxer de configuració de host virtual al primer servidor Apache:

    nano /var/www/html/web2.html

    Exemple de codi HTML:

    <!DOCTYPE html>
<html>
<head>
<title>Servidor Web Apache 2</title>
</head>
<body>
<h2>Pàgina del Servidor Web Apache 2!</h2>
</body>
</html>

    Crear el fitxer de configuració del host virtual:

    nano /etc/apache2/sites-enabled/web2.conf

    Afegir les següents configuracions:

    <VirtualHost *:80> 
    ServerName web2.iaw2425.com 
    ServerAdmin webmaster@localhost 
    DocumentRoot /var/www/html 
    DirectoryIndex web2.html 
    ErrorLog ${APACHE_LOG_DIR}/error.log 
    CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>

    Caldrà reiniciar el servei Apache:

    systemctl restart apache2

    Crear el Balancejador de Càrrega Apache

    Configurar el tercer servidor com un servidor de balanceig de càrrega per redirigir tot el trànsit a tots dos servidors web backend.

    Habilitar els mòduls intermediaris al servidor de balanceig de càrrega:

    a2enmod proxy
a2enmod proxy_http
a2enmod proxy_balancer
a2enmod lbmethod_byrequests

    Mòduls d’Apache

    • El servidor intermediari: Habilita el mòdul intermediari d’Apache.
    • Proxy_http: Habilita el mòdul de proxy HTTP d’Apache.
    • Proxy_balancer: Habilita el mòdul de balancejador de càrrega d’Apache.

    Reiniciar el servei Apache:

    systemctl restart apache2

    Verificar tots els mòduls intermediaris:

    apachectl -M | grep proxy

    Crea un fitxer de configuració d’Apache per al balanceig de càrrega:

    nano /etc/apache2/sites-enabled/loadbalancer.conf

    Afegir les següents configuracions:

    <VirtualHost *:80>
    ServerName balancer.iaw2425.com
    <Proxy balancer://webserver>
        # servidor 1
        BalancerMember http://web1.iaw2425.com
        #BalancerMember http://IP_HTTP_SERVER_1:80

        #servidor 2
        BalancerMember http://web2.iaw2425.com
        #BalancerMember http://IP_HTTP_SERVER_1:80

        ProxySet stickysession=ROUTEID
    </Proxy>
    ProxyPreserveHost On
    ProxyPass / balancer://webserver/
    ProxyPassReverse / balancer://webserver/
</VirtualHost>

    Configuració de la Política de Balanceig de Càrrega

    Per configurar la política de balanceig de càrrega cal tenir activat prèviament el mòdul proxy_balancer amb la següent ordre:

    sudo a2enmod proxy_balancer

    El balanceig de càrrega de tipus Round Robin consisteix en distribuir les peticions entre els servidors de manera seqüencial, de manera que cada vegada que arribe una nova petició s’envia al següent servidor de la llista de servidors configurats al servidor Apache. Per activar aquest mètode de balanceig hem d’activar el mòdul lbmethod_byrequests:

    sudo a2enmod lbmethod_byrequests

    Aquest mètode de balanceig també permet distribuir les peticions entre els servidors en funció dels paràmetres lbfactor i lbstatus. Pots consultar més informació sobre aquest mòdul a la documentació oficial.

    Habilitat el VirtualHost del Balancejador

    Habilitem el VirtualHost que acabem de crear amb la següent ordre:

    sudo a2ensite loadbalancer.conf

    Deshabilitarem el VirtualHost que té Apache configurat per defecte:

    sudo a2dissite 000-default.conf

    Consultar els VirtualHost que té habilitats Apache amb l’ordre:

    sudo apache2ctl -S

    Després d’habilitar els mòduls, i activar el VirtualHost, caldrà reiniciar el servei d’Apache:

    systemctl restart apache2

    Verificar el Balanceig de Càrrega amb Apache

    Si des del navegador web s’accedeix al balancejador de càrrega utilitzant la URL http://balancer.iaw2425.com. S’hauria de veure la pàgina del primer servidor backend. Si esperem un temps i actualitzem la pàgina, s’hauria de veure la pàgina HTML del segon servidor backend. I així successivament.

    Balancejador amb Nginx¶

    Requisits previs:

    • 3 servidors amb Nginx instal·lat
    • Configuració de noms de domini

    Configuració dels Servidors d’aplicacions

    En el primer servidor d’aplicacions, suprimir el fitxer index.html per defecte i crear-ne un de nou:

    # rm -rf /var/www/html/index.html
# nano /var/www/html/index.html

    Afegir les línies següents:

    <!DOCTYPE html>
<html>
<head>
<title>Servidor Web 1</title>
</head>
<body>
Server 1
</body>
</html>

    En el segon servidor, procedirem de la mateixa manera, suprimint i refent el index.html:

    # rm -rf /var/www/html/index.html
# nano /var/www/html/index.html

    Afegir les línies següents:

    <!DOCTYPE html>
<html>
<head>
<title>Servidor Web 2</title>
</head>
<body>
Server 2
</body>
</html>

    Configura el balancejador de càrrega

    Per continuar, haureu de configurar un servidor balancejador de càrrega que distribueix la càrrega entre els dos servidors d’aplicacions.

    Primer, caldrà elimimnar el fitxer de configuració per defecte de Nginx i crear un fitxer de configuració nou per al balancejador de càrrega:

    # rm -rf /etc/nginx/sites-enabled/default
# nano /etc/nginx/conf.d/load-balancing.conf

    Afegir les línies següents:

    upstream backend {
        server 192.168.10.11;
        server 192.168.10.12;
    }

    server {
        listen      80;
        server_name loadbalancing.example.com;

        location / {
            proxy_redirect      off;
            proxy_set_header    X-Real-IP $remote_addr;
            proxy_set_header    X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header    Host $http_host;
        proxy_pass http://backend;
    }
}

    Per a utilitzar el mètode Least_conn, ho indicariem en upstream backend:

    upstream backend {
        least_conn;
        server 192.168.10.11;
        server 192.168.10.12;
    }

    Per a utilitzar el mètode Ip_hash, ho indicariem així:

    upstream backend {
    ip_hash;
        server 192.168.10.11;
        server 192.168.10.12;
    }

    Per a verificar que no hi ha errors de sintaxis en la configuració de Nginx:

    # nginx -t

    Reiniciar el servei de Nginx:

    # systemctl restart nginx

    Verificar el Balanceig de Càrrega amb Nginx

    De la mateixa manera que en Apache. Des del navegador web s’accedirà al balancejador de càrrega utilitzant la seua URL. S’hauria de veure la pàgina del primer servidor i, si esperem un temps i actualitzem la pàgina, s’hauria de veure la pàgina HTML del segon servidor. I així successivament.
