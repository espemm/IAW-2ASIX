    Pràctica¶

    WordPress en Docker¶¶

    Per crear un bloc amb WordPress necessitem tenir una base de dades on emmagatzemar les entrades. Així que començarem creant-la i després crearem el contenidor del nostre bloc.

    Crear un contenidor amb MariaDB

    WordPress suporta els motors relacions MySQL i MariaDB. Utilitzarem MariaDB

    Example

    Crearem la base de dades usant aquest volum.

    docker run -d --name wordpress-db \ 
    --mount source=wordpress-db,target=/var/lib/mysql \ 
    -e MYSQL_ROOT_PASSWORD=secret \ 
    -e MYSQL_DATABASE=wordpress \ 
    -e MYSQL_USER=manager \ 
    -e MYSQL_PASSWORD=secret mariadb:10

    La imatge es descarregarà, si no ho estava ja, i s’iniciarà el nostre contenidor de MariaDB:

    $ docker run -d --name wordpress-db \ 
    --mount source=wordpress-db,target=/var/lib/mysql \ 
    -e MYSQL_ROOT_PASSWORD=secret \ 
    -e MYSQL_DATABASE=wordpress \

    El primer que haurem notat és que el contenidor no es queda en primer pla. El paràmetre -d indica que cal executar-lo com un procés en segon pla. Així no podrem aturar-ho per accident amb Ctrl+C.

    En segon lloc, veiem que el contenidor fa servir un port, el 3306/tcp, però no està linkat a la màquina amfitrió. No tenim cap manera d’accedir a la base de dades directament. La nostra intenció és que només el contenidor de WordPress hi pugui accedir.

    Finalment tenim una sèrie de paràmetres -e (de entorn) que ens permet configurar la nostra base de dades.

    Info

    Els contenidors es configuren a través de variables d’entorn, que podem configurar amb el paràmetre -e que veiem a l’ordre anterior. Gràcies a ells hem creat una base de dades, un usuari i configurat les contrasenyes.

    Tip

    Es recomana cercar al registre de Docker la imatge oficial de MariaDB per entendre l’ús dels paràmetres.

    Finalment, el paràmetre –mount ens permet enllaçar el volum que creem en el pas anterior amb el directori /var/lib/mysql del contenidor. Aquest directori és on es guarden les dades de MariaDB. Això significa que si esborrem el contenidor, o actualitzem el contenidor a una nova versió, no perdrem les dades perquè ja no estàn ahí, sinó en el volum. Només ho perdríem si esborrarem explícitament el volum.

    Warnning

    Cada contenidor que fem servir tindrà un o diversos directoris on s’han de desar les dades no volàtils. Ens correspon a nosaltres conèixer l’eina i saber quins directoris es tracten. Usualment són a la documentació del contenidor, però no sempre.

    Crear la web

    Crearem el nostre contenidor de WordPress, connectant-lo amb la nostra base de dades. A més, volem poder editar els fitxers de les plantilles, per si hem de modificar alguna cosa, així que necessitarem muntar el directori del contenidor on està instal·lat WordPress amb el nostre compte d’usuari a la màquina amfitrió.

    Example

    Crearem l’espai de treball:

    mkdir -p ~/Sites/wordpress/target && cd ~/Sites/wordpress

    Example

    I dins aquest directori arrenquem el contenidor:

    docker run -d --name wordpress \ 
    --link wordpress-db:mysql \ 
    --mount type=bind,source="$(pwd)"/target,target=/var/www/html \ 
    -e WORDPRESS_DB_USER=manager \ 
    -e WORDPRESS_DB_PASSWORD=secret \ 
    -p 8080:80 \ 
    wordpress:6

    Quan acabe l’execució, podrem accedir a l’adreça http://localhost i finalitzar les passes d’instal·lació.

    Si llistem el directori target comprovarem que tenim tots els fitxers d’instal·lació accessibles des del directori amfitrió.

    WordPress amb Compose¶¶

    Per automatitzar la creació, l’inici i la parada d’un contenidor o un conjunt podem utilitzar Docker Compose.

    Començarem per parar i esborrar el que hem creat:

    Example

    docker contenidor stop wordpress wordpress-db
docker contenidor rm wordpress wordpress-db
docker volume rm wordpress-db

    Docker Compose

    Compose és una eina per definir i executar aplicacions multicontenidor. Amb una sola comanda podrem crear i iniciar tots els serveis que necessitem per a la nostra aplicació.

    Els casos d’ús més habituals per a docker compose són:

    • Entorns de desenvolupament
    • Entorns de testeig automàtics (integració continua)
    • Desplegament en host individuals (no clusters)

    Compose té ordres per manejar tot el cicle de vida de la nostra aplicació, com ja hem vist:

    • Iniciar, aturar i refer serveis.
    • Vore l’estat dels serveis.
    • Visualitzar els logs.
    • Executar una ordre en un servei.

    Creació de contenidors automatitzada

    Al mateix directori on estàvem al pas anterior (~/Sites/wordpress), crearem un fitxer anomenat docker-compose.yaml amb el contingut següent:

    services:
    db:
        image: mariadb:10
        volumes:
            - data:/var/lib/mysql
        environment:
            - MYSQL_ROOT_PASSWORD=secret
            - MYSQL_DATABASE=wordpress
            - MYSQL_USER=manager
            - MYSQL_PASSWORD=secret
    web:
        image: wordpress:6
        depends_on:
            - db
        volumes:
            - ./target:/var/www/html
        environment:
            - WORDPRESS_DB_USER=manager
            - WORDPRESS_DB_PASSWORD=secret
            - WORDPRESS_DB_HOST=db
            - WORDPRESS_DB_NAME=wordpress
        ports:
            - 8080:80
volumes:
    data:

    Info

    Els fitxers de Compose estan dividits en tres seccions: services, volums i networks; i heu d’indicar un número de versió. Ens permet fer pràcticament el mateix que podem fer amb el client de docker, però de forma automàtica.

    En aquest fitxer podem fer el mateix que hem fet anteriorment, però amb l’avantatge de descriure tots els requisits en un sol fitxer.

    Iniciar serveis

    Arrancada de l’aplicació amb Compose:

    docker compose up -d

    Quan arrenquem l’aplicació, Compose ens informa dels serveis que ha anat aixecant:

    $ docker compose up -d
Creating network "wordpress_default" with the default driver
Creating volume "wordpress_data" with local driver
Creating wordpress_db_1 ...
Creating wordpress_db_1 ... done
Creating wordpress_web_1 ...
Creating wordpress_web_1 ... done

    El paràmetre -d és similar al que hem vist a docker run: ens permet aixecar els serveis en segon pla.

    Vore els contenidors actius:

    $ docker container ls
CONTAINER ID     IMAGE          COMMAND     CREATED     STATUS          PORTS               NAMES
a07b5d4d3982    wordpress:6 "docker.s…"   10 seconds ago Up 8 seconds 0.0.0.0:8080->80/tcp wordpress_web_1
d9204884cec5 mariadb:10 "docker.s…" 11 seconds ago Up 10 seconds 3306/tcp wordpress_db_1

    També podem vore els contenidors amb Compose:

    $ docker compose ps 
Name                    Command                     State        Ports
-------------------------------------------------------------------------------
wordpress_db_1      docker-entrypoint.sh mysqld     Up          3306/tcp
wordpress_web_1     docker-entrypoint.sh apach ...  Up          0.0.0.0:8080->80/tcp

    Hem de tenir en compte el següent:

    • docker compose ps només mostra informació dels serveis que es defineix a docker-compose.yaml, mentre que docker mostra tots.
    • Quan creem contenidors amb docker sense indicar un nom, per defecte n’assigna un aleatori; mentre que a Compose el prefix és el nom del directori i el sufix el nom del servei: wordpress_db_1. El número indica el número d’instància. Podeu aixecar més d’una instància d’un mateix servei.

    Si accedim a l’adreça http://localhost:8080/, tornarem a veure la instal·lació de WordPress.

    Aturar serveis

    docker compose stop

    Esborrar serveis

    docker compose down

    Això esborra els contenidors, però no els volums. Així que si hem creat bé l’aplicació les nostres dades estan fora de perill.

    Si volem esborrar també els volums:

    docker compose down -v

    Estructura de la configuració

    Vegem la configuració per parts:

    volums: 
    data:

    Ja hem indicat que és important desar les dades volàtils de les aplicacions en volums. En aquest cas hem creat un volum anomenat data. Recordem que Compose sempre afegeix com a prefix el nom del directori, de manera que el nom real del volum és wordpress_data. Podem comprovar-ho amb el client de docker com vam fer al capítol de volums:

    $ docker volume ls
DRIVER     VOLUM NAME
local      wordpress_data

    Ens saltem la secció de xarxes (networks) i anem a la secció de serveis, que són els contenidors que necessita o componen la nostra aplicació.

    Primer la base de dades: docker-compose.yaml

    services: 
  db: 
    image: mariadb:10 
    volumes: 
      - data:/var/lib/mysql 
    environment: 
      - MYSQL_ROOT_PASSWORD=secret 
      - MYSQL_DATABASE=wordpress 
      - MYSQL_USER=manager 
      - MYSQL_PASSWORD=secret

    Després d’obrir la part de serveis, el primer nivell indica el nom del servei db que genera el contenidor wordpress_db. El que veiem a continuació és el mateix que vam fer a la secció anterior però de forma parametritzada. Si recordem, per alçar la nostra base de dades, indiquem la imatge (línia 3), després muntem els volums (línia 4), i després indiquem les variables d’entorn que configuraràn el contenidor (línia 6).

    És a dir, això és equivalent, excepte pel nom, a:

    $ docker run -d --name wordpress-db \ 
    --mount source=wordpress-db,target=/var/lib/mysql \ 
    -e MYSQL_ROOT_PASSWORD=secret \ 
    -e MYSQL_DATABASE=wordpress \ 
    -e MYSQL_USER=manager \ 
    -e MYSQL_PASSWORD=secret mariadb:10

    I després el WordPress: docker-compose.yaml

    services: 
  web: 
    image: wordpress:6 
    depends_on: 
      - db 
    volumes: 
      - ./target:/var/www/html 
    environment: 
      - WORDPRESS_DB_USER=manager 
      - WORDPRESS_DB_PASSWORD=secret 
      - WORDPRESS_DB_HOST=db 
    ports: 
      - 8080:80

    En aquest cas l’equivalència és a l’ordre:

    $ docker run -d --name wordpress \ 
    --link wordpress-db:mysql \ 
    --mount type=bind,source="$(pwd)"/target,target=/var/www/html \ 
    -e WORDPRESS_DB_USER=manager \ 
    -e WORDPRESS_DB_PASSWORD=secret \ 
    -p 8080:80 \ 
    wordpress:6

    L’equivalència dels paràmetres és la següent:

    paràmetre Docker paràmetre Composer
    –link depends_on
    –mount volumes
    -e environment
    -p,–publish ports
    image

    Note

    Si reiniciamos el ordenador, los contenedores estarán detenidos (stop), podremos reiniciarlos con docker start o docker compose start. Este es el comportamiento predeterminado y el que nos interesa en un entorno de desarrollo.

    Sin embargo, en otros entornos, o para casos concretos, igual queremos que un contenedor tenga el mismo estado en el que estaba antes de reiniciar la máquina (iniciado o parado).

    Para eso usaremos el parámetro restart. En el caso de la base de datos de nuestro ejemplo, la configuración quedaría como:

    docker-compose.yaml

    services:
    db:
       image: mariadb:10
       restart: unless-stopped
       volumes:
           - data:/var/lib/mysql
       environment:
           - MYSQL_ROOT_PASSWORD=secret
           - MYSQL_DATABASE=wordpress
           - MYSQL_USER=manager
           - MYSQL_PASSWORD=secret

    El equivalente en la consola sería:

    $ docker run -d --name wordpress-db \
    --restart unless-stopped
    --mount source=wordpress-db,target=/var/lib/mysql \
    -e MYSQL_ROOT_PASSWORD=secret \
    -e MYSQL_DATABASE=wordpress \
    -e MYSQL_USER=manager \
    -e MYSQL_PASSWORD=secret mariadb:10
    Otros valores son: no (por defecto), always y on-failure
